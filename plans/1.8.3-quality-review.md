## Native crash investigation

The existing local build environment contained extra pywebview files including
`webview/js/customize 2.js`. pywebview loads every JavaScript file there; the extra
copy lacks the parameter substitution associated with `customize.js`. Calling
the loader reproduced `KeyError: 'text_select'`; the packaged app aborted through
the Cocoa navigation callback.

A fresh environment installed from the hash-pinned requirements produced an app
that started and passed all 56 package smoke checks. The PyInstaller spec now
refuses missing, modified or unexpected pywebview JavaScript, comparing it with
the installed wheel's RECORD. Reinstalling over an old environment is insufficient
because pip does not remove untracked copies.

The user's supplied trace excerpt contains native thread frames rather than the
full exception and executable provenance. Its callback path is consistent with
the reproduced crash; it does not prove that every published 1.8.2 artifact has
the same defect. The old local environment was preserved for diagnosis.

## Additional security hardening

- Registered both PIN and UV unlocks before they wait for device access. Lock,
  disconnect and dialog cancellation reach queued PIN requests; cancelled results
  cannot enter the token cache. An already transmitted PIN attempt cannot be undone.
- Replaced HID-path-derived runtime IDs with fresh connection IDs. Polling detects
  changes in observable identity and publishes disconnect before reconnect,
  invalidating the old authorization. CTAP sessions recheck the current record,
  VID/PID, product, AAGUID and available serial; management-only serials are read
  over the opened HID connection. Normal polls retain the current connection ID.
- Serialized connection/update callbacks and suppressed late updates from retired
  records, in both scanner and UI. Old attestation cannot restore a removed UI key.
- Moved PIV/OpenPGP overwrite checks inside the same card connection and reader
  lock as key generation; moved OTP checks inside its programming locks. Read
  failures abort before writing. PIV aliases such as `0x9a` cannot bypass an occupied
  `9a` slot, and the reserved attestation slot is refused as a generation target.

Regression coverage: queued and in-flight PIN cancellation; HID replacements,
management-only serials, queued stale sessions and late attestation; PIV aliases,
reserved slots, failed occupancy reads, strict confirmation flags, same-connection
checks and simultaneous generation requests; OTP lock coverage; cancelled PIN
dialogs and stale connection events in the browser.

Limitations: device-reported identity is not cryptographic proof; anonymous
same-model keys swapped between polls can be indistinguishable. The underlying
descriptor lookup/open race and full CCID/OTP identity binding are not solved.
Application locks do not exclude other processes. Older PIV firmware without
slot metadata cannot reliably reveal a key after its certificate was removed.
Physical-device checks and the Windows/Linux candidate builds remain release gates.
